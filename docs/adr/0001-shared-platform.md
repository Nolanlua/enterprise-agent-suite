# ADR 0001：两个 Agent 共享数据中台与评测中台

## 状态

已采纳。

## 背景

岐黄智库和零售订货 Agent 的数据、权限、评测标准不同，但都需要：

- 数据目录和质量门禁；
- 特征/检索数据服务；
- 评测集版本和回归报告；
- 统一日志、Tracing、成本统计。

如果每个 Agent 各建一套，会出现：

- 指标口径不一致；
- 权限模型重复实现；
- 评测脚本各写一份；
- 运维成本翻倍。

## 决策

采用一个仓库、两套 Agent、两套共享中台的架构：

- 数据中台和评测中台独立部署；
- Agent 通过 HTTP 客户端访问中台；
- 订单服务独立部署；
- 公共配置、鉴权、日志放在 packages/common。

## 后果

优点：

- 口径统一；
- 权限和审计统一；
- 评测门禁统一；
- 两个 Agent 可以独立扩容和发布。

代价：

- 仓库变大，需要 workspace 和 CI 分片；
- 中台故障会影响两个 Agent；
- 需要明确中台与 Agent 的接口契约。

## 不采用

- 单体应用：早期快，后期耦合；
- 两个独立仓库：重复建设，口径漂移；
- 每个 Agent 一套中台：运维成本高，不适合企业。
